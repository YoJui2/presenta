2 · ¿Qué es la validación cruzada?

¿Qué es la validación cruzada?

Un procedimiento de remuestreo que divide los datos en pliegues y rota cuál se usa para evaluar.

5 · Tipos y estrategias de validación cruzada

No todos los datos se validan igual

Hold-out

Una división 80/20 o 70/30. Rápida, pero sensible al corte.

K-Fold

Uso general. Habitualmente k = 5 o 10.

Stratified K-Fold

Conserva la proporción de clases. Ideal para clasificación desbalanceada.

TimeSeriesSplit

Respeta el orden temporal. Nunca entrena con el futuro.

GroupKFold

Mantiene juntos grupos relacionados para evitar contaminación.

LOO / LPO

Deja una o p observaciones afuera. Poco sesgo, alto costo.

6 · Métricas de evaluación

La media importa. La dispersión también.

Accuracy

Proporción total de predicciones correctas.

Precision · Recall

Importantes cuando los falsos positivos y negativos tienen costos diferentes.

F1-score

Media armónica entre Precision y Recall.

ROC-AUC · Confusión

Capacidad discriminativa y detalle de tipos de error.

Reporte: media ± desviación estándar

Media alta + desviación baja suele ser una señal más confiable que una única métrica máxima.

7 · Implementación técnica en Scikit-Learn

Una evaluación reproducible con Scikit-Learn

Observaciones · cross_val_score

Se calcula una métrica por fold. La media resume el rendimiento y una desviación estándar baja indica resultados más consistentes entre particiones.

cross_val_score()

Automatiza la validación cruzada y devuelve una métrica por fold. Permite estimar rápidamente el rendimiento sin particionar, entrenar y evaluar manualmente en cada iteración.

cross_validate()

Evalúa varias métricas a la vez, como accuracy, precision, recall y F1. Es útil cuando una sola medida no alcanza para describir el comportamiento del modelo.

cross_val_predict()

Genera predicciones out-of-fold para todas las observaciones: cada una proviene de un modelo que no la usó al entrenar. Así se pueden analizar errores, por ejemplo con una matriz de confusión.

8 · Balance comparativo · Ventajas

¿Qué aporta la validación cruzada?

Estimación más robusta

Promedia el rendimiento obtenido en varios folds y ofrece una estimación más estable que una sola partición. Ayuda a anticipar cómo responderá el modelo ante datos no vistos.

Menos sesgo de partición

Reduce la dependencia de un único corte aleatorio, que podría resultar inusualmente fácil o difícil. Así, las conclusiones dependen menos de qué observaciones quedaron en test.

Aprovecha los datos

En cada iteración, una parte distinta se reserva para evaluar y el resto se usa para entrenar. Al completar los folds, todas las observaciones han participado en ambas etapas.

Comparación justa

Evaluar distintos modelos con los mismos folds permite comparar sus resultados bajo condiciones equivalentes. Esto hace más reproducible la elección del modelo.

Mejor diagnóstico

La media y la variación entre folds muestran tanto el rendimiento como su estabilidad. Diferencias entre entrenamiento y evaluación también pueden advertir sobreajuste.

Apoya la búsqueda

Permite evaluar sistemáticamente distintas configuraciones de hiperparámetros. Por eso se utiliza en herramientas como Grid Search y Random Search.

8 · Balance comparativo · Limitaciones

¿Cuándo hay que tener cuidado?

Mayor costo computacional

Entrenar k modelos cuesta aproximadamente k veces más que una sola evaluación.

Respeta la estructura de los datos

Para series temporales o grupos, usa divisiones específicas como TimeSeriesSplit o GroupKFold.

No siempre escala

En conjuntos enormes, un hold-out representativo puede ser más práctico.

Evita la fuga de datos

Incluye el preprocesamiento en un Pipeline para ajustarlo dentro de cada fold.

9.1 · Buenas prácticas

Data leakage: cuando el futuro se filtra al entrenamiento

Código · Práctica incorrecta

La salida aparecerá aquí...

✕ Práctica incorrecta · Data leakage

Si el escalador se ajusta con todo X antes de validar, también aprende de los datos que luego serán test. Esa información se filtra al entrenamiento y puede sesgar la evaluación.

✓ Práctica correcta · Pipeline

Al incluir el escalador en un Pipeline, se ajusta sólo con los datos de entrenamiento de cada fold. El fold de test se transforma sin participar en el aprendizaje.

Observación del código · Práctica incorrecta

El scaler se ajusta antes de separar los folds y usa las 200 observaciones, incluidas las de test. Aunque la métrica coincida con la práctica correcta, la evaluación queda contaminada.
