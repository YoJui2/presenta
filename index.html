Introducción

Entrenar bien no significa generalizar bien

A

Memorización

El modelo aprende también el ruido del conjunto de entrenamiento.

Resultado: rendimiento alto en train.

B

Generalización

El modelo responde correctamente ante observaciones nuevas e independientes.

Objetivo: rendimiento confiable en producción.

La pregunta no es “¿qué tan bien recuerda?”, sino “¿qué tan bien predice lo que todavía no vio?”

2 · ¿Qué es la validación cruzada?

¿Qué es la validación cruzada?

Un procedimiento de remuestreo que divide los datos en pliegues y rota cuál se usa para evaluar.

Particionar
dividir en folds
→
Entrenar
con k − 1 folds
→
Evaluar
con el fold restante
→
Resumir
media + dispersión

Cada observación aparece en validación exactamente una vez dentro del ciclo K-Fold.

5 · Tipos y estrategias de validación cruzada

No todos los datos se validan igual

Hold-out

Una división 80/20 o 70/30. Rápida, pero sensible al corte.

K-Fold

Uso general. Habitualmente k = 5 o 10.

Stratified K-Fold

Conserva la proporción de clases. Ideal para clasificación desbalanceada.

TimeSeriesSplit

Respeta el orden temporal. Nunca entrena con el futuro.

GroupKFold

Mantiene juntos grupos relacionados para evitar contaminación.

LOO / LPO

Deja una o p observaciones afuera. Poco sesgo, alto costo.

6 · Métricas de evaluación

La media importa. La dispersión también.

Accuracy

Proporción total de predicciones correctas.

Precision · Recall

Importantes cuando los falsos positivos y negativos tienen costos diferentes.

F1-score

Media armónica entre Precision y Recall.

ROC-AUC · Confusión

Capacidad discriminativa y detalle de tipos de error.

Reporte: media ± desviación estándar

Media alta + desviación baja suele ser una señal más confiable que una única métrica máxima.

7 · Implementación técnica en Scikit-Learn

Una evaluación reproducible con Scikit-Learn

Salida aparecerá aquí...

cross_val_score()

Automatiza la validación cruzada y devuelve una métrica por fold. Permite estimar rápidamente el rendimiento sin particionar, entrenar y evaluar manualmente en cada iteración.

cross_validate()

Evalúa varias métricas a la vez, como accuracy, precision, recall y F1. Es útil cuando una sola medida no alcanza para describir el comportamiento del modelo.

cross_val_predict()

Genera predicciones out-of-fold para todas las observaciones: cada una proviene de un modelo que no la usó al entrenar. Así se pueden analizar errores, por ejemplo con una matriz de confusión.

8 · Balance comparativo

Potente, pero no automática

Ventajas

  • Estimación más robusta.
  • Uso integral del corpus.
  • Comparación reproducible.
  • Diagnóstico de sobreajuste.

Limitaciones

  • Multiplica el costo computacional.
  • No respeta por sí sola tiempo o grupos.
  • Puede ser innecesaria en Big Data.
  • Es vulnerable al data leakage.
9.2 · Buenas prácticas

Data leakage: cuando el futuro se filtra al entrenamiento

✕ Incorrecto

Escalar o imputar usando todo X antes de validar.

El fold de test “enseña” sus medias y varianzas.

✓ Correcto

Encapsular el preprocesamiento dentro de un Pipeline.

Cada transformación aprende sólo con los datos de train.

from sklearn.pipeline import make_pipeline

pipe = make_pipeline(StandardScaler(), modelo)
scores = cross_val_score(pipe, X, y, cv=5)
9.1 · Compromiso sesgo–varianza

El compromiso sesgo–varianza

k bajo

Menos datos para entrenar por vuelta.

Mayor sesgo · menor costo

k = 5 o 10

Equilibrio empírico entre entrenamiento, estabilidad y costo.

Recomendación habitual

k alto / LOOCV

Casi todo el dataset entrena, pero las estimaciones se correlacionan.

Menor sesgo · mayor varianza

El mejor valor de k depende del tamaño, la estructura y el costo de los errores del problema.
